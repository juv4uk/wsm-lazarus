# Відображення `eval`/`apply` Маккарті на клітинки `wsm.nativeeval`

**Навіщо цей документ.** Доведено числом: `external/sens/lib/core1.lisp` має
**96 визначень, і всі 96** уживають `функція` або `мітка`
(`knowledge/core1-poverhnia.md`). Без них Core1 не виконується жодним
визначенням. Тут — точне відображення того, що треба додати, на **наявну**
модель клітинок, щоб не вигадувати нову.

## Що є зараз

```pascal
TNativeCellKind = (ncEmpty, ncDomain, ncPair);
TNativeCell = record
  Kind: TNativeCellKind;
  Key:  TDomainKey;
  First, Rest: SizeInt;   { індекси в FCells }
end;

function TNativeEvaluator.Eval(N: TSourceNode; Depth: SizeInt): SizeInt;
```

`Eval` **не має параметра середовища**. Це не недогляд — модуль прямо
обмежений шістьма D3-операціями.

## Що додати — рівно три речі

### 1. Вид клітинки для закриття

```pascal
TNativeCellKind = (ncEmpty, ncDomain, ncPair, ncClosure);
```

`ncClosure` використовує наявні поля без нового запису:
- `First` — індекс у `FCells` на **список параметрів** (як `ncPair`-ланцюг);
- `Rest`  — індекс на **тіло** (той самий ланцюг);
- `Key`   — не використовується (порожній), бо закриття не має доменної адреси.

**Чому не нове поле:** `TNativeCell` уже має два індекси й ключ. Додавання
поля змінює розмір запису й ламає всі наявні місця; використання наявних
полів — ні.

### 2. Середовище як аліста — те саме, що `pairlis`

Маккарті: `pairlis[x; y; a] = [null[x] -> a; T -> cons[cons[car[x]; car[y]];
pairlis[cdr[x]; cdr[y]; a]]]`.

У клітинках це вже вміє `ncPair`:
```
оточення := ncPair( ncPair(ім'я, значення), попереднє-оточення )
```
`ядро1-поєднати-параметри` (`core1.lisp:193`) будує саме таку структуру —
воно й стає `pairlis`. **Нічого нового писати не треба, треба дати йому
виконуватись.**

### 3. Третій параметр `Eval`

```pascal
function Eval(N: TSourceNode; Depth: SizeInt; Env: SizeInt): SizeInt;
```

`Env` — індекс клітинки-оточення (`ncEmpty` = порожнє). Для атома:
1. спершу `ncDomain` — ратифікований ключ (як зараз);
2. якщо ключа немає — пошук в `Env` (це `assoc`);
3. якщо немає й там — `Fail('unknown binding')`.

**Порядок важливий:** доменні ключі лишаються першими, щоб `так`, `ні`,
`як-є` не могли бути затінені параметром. Це не зміна семантики — це
збереження наявної.

## Чотири функції Маккарті — де вони вже є

| Маккарті | Що робить | Де в проєкті |
|---|---|---|
| `eval` | диспетч за головою | `Eval`, `case Key.Bits` |
| `evcon` | ліниві гілки | `Eval`, гілка `%110` — **уже є** |
| `evlis` | обчислити аргументи | **немає** — додати цикл перед `apply` |
| `pairlis` | зв'язати параметри | `ядро1-поєднати-параметри` (Lisp) |
| `assoc` | знайти в алісті | `ядро1-знайти-в-оточенні` (Lisp) |
| `apply` | застосувати | **немає** — `ncClosure` + `evlis` + `pairlis` |
| `appq` | загорнути в `цитата` | **немає** — і без нього значення обчислиться вдруге |

## `appq` — чому він обов'язковий

```
appq[m] = [null[m] -> NIL; T -> cons[list[QUOTE; car[m]]; appq[cdr[m]]]]
```

Коментар у `mccarthy-kernel.s:1626` пояснює причину: `evlis` уже обчислив
значення один раз; якщо подати їх у `eval` без `QUOTE`, вони обчисляться
**вдруге як код**. Наприклад реалізований список `(а)` буде сприйнятий як
«викликати `а` без аргументів», а не як дане.

У проєкті `цитата` — це `як-є` (`d3.lisp:15`, ключ `%001`).

## Порядок роботи

1. `ncClosure` + поле-вільне використання `First`/`Rest`.
2. `Env` як третій параметр `Eval`; пошук атома після доменного ключа.
3. `функція` у голові форми: побудувати `ncClosure`.
4. `evlis` — обчислити аргументи з `Env`.
5. `appq` — загорнути кожен у `як-є`.
6. `pairlis` — уже в Lisp, але для швидкості можна й у Pascal.
7. `мітка` — те саме, плюс зв'язати ім'я із самим закриттям в `Env`.

**Критерій готовності:** `knowledge/core1-poverhnia.md` показує 96 із 96,
і хоча б `ядро1-другий-елемент` реально викликається з фізичним
аргументом. Не «компілюється» — **викликається**.

## Чого цей документ НЕ робить

Не вводить нових доменів, нових бітів і не змінює жодного закону.
`ncClosure` — це фізичний тег контейнера, як `ncPair`, а не мовна функція.
Закони лишаються в pinned `juv4uk/sens`.
