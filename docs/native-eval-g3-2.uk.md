# G3.2: обмежене нативне виконання D3

Задача: [#44](https://github.com/juv4uk/wsm-lazarus/issues/44), parent [#41](https://github.com/juv4uk/wsm-lazarus/issues/41). CLAIM: [6478366799](https://github.com/juv4uk/wsm-lazarus/issues/44#issuecomment-6478366799), [уточнення власника щодо оракула](https://github.com/juv4uk/wsm-lazarus/issues/44#issuecomment-6478498655).

## Що реально виконується

Новий `wsm.nativeeval` приймає **одну** структурно розібрану `.lisp`-проєкцію, зв'язує її голови через чинний `wsm.bindindex` і виконує п'ять D3-механізмів. Dispatch перевіряє **і ширину 3, і точні біти**: `001`, `010`, `011`, `100`, `111`. Це поточні координати, не історичні байтові SID. Інші голови відхиляються як непідтримані, навіть коли є в таблиці домену.

Людські назви потрібні лише binder-у. Значення `D1:0`, `D1:1` та порожня структура `D3:000` зберігаються окремо; жодної host-truthiness або перетворення порожнього списку на false немає. Предикат `D3:010` повертає саме D1.

Реальні приклади:

```text
(сполучити так ())                   → (1)
(сполучити так ні)                   → (1 . 0)
(перше (сполучити ні ()))             → 0
(решта (сполучити так ()))            → ()
(атом? ())                          → 1
(атом? (сполучити так ()))            → 0
(як-є кіт)                          → (1110010 1110011 1101110)
```

Біти в правій колонці — відображення результату. Ширина всередині значення збережена явно: одиничний D1 не стає числом, D7-координата не виводиться з байта чи довжини printable-тексту. Цей printer не є канонічним `.sens` serializer.

## Джерело законів і фізичний доказ

**Першоджерело:** pinned `external/sens`, commit `1f1bf676eeac605e065035d9dd2adaae807f1788`, `contracts/language-contract-12.lisp` та закони D3 L1–L5, на які він посилається. `lib/domains/d1.lisp`, `d3.lisp`, `d7.lisp` — лише проєкції. Таблиця імен сама по собі не встановлює право виклику.

**Корекція власника:** старий oracle/SID8-шлях не використовуємо. Contract 12.0 прямо каже, що український `.lisp` не є оракулом; усі активні SID8/Sens8/Function8-шляхи заборонені. Metadata `refs/tier1-baseline.properties` ще містить major=9, але це не дозвіл повертатися до старого контракту; цей pin/metadata scope тут не змінюється.

`scripts/nativeeval-witness.py` перевіряє pin і чистоту upstream source, наявність Contract 12.0 та для кожного випадку:

1. Передає українську проєкцію **pinned SENS** для `--t5m-mint`.
2. Зберігає реальний двійковий `.sens` carrier і його SHA-256.
3. Виконує **фізичний `.sens`**, а не текст у REPL. У pinned CLI це `Zig/T5M → ExactDomainWord → PhysicalT5Program → Session::bare`, без неявного Core4 чи legacy reader.
4. Зіставляє stdout підтриманої форми з FPC або підтверджує відмову обох механізмів для невалідного випадку. Відмова не означає однаковий текст чи повну класифікацію помилок.

Локально пройдено **19 позитивних і 5 негативних фізичних свідків**. Це узгодженість конкретних механізмів із законом SENS на цьому pin, не незалежна ратифікація закону й не вся семантика мови.

## Представлення, allocation та lifetime

`TNativeCell` — фізичний record з тегом контейнера (`empty/domain/pair`), точним `TDomainKey` або двома `SizeInt`-індексами. Це теги пам'яті Pascal, не enum мовних законів. На x86-64 `SizeInt` має 8 байтів; фактичний `SizeOf(TNativeCell)` друкує тест, щоб не підміняти layout припущенням.

Клітини лежать у динамічному масиві. Handle — індекс, а не адреса: `SetLength` може перемістити масив, не зламавши pair-посилання. Індекс 0 містить окремий empty-tag із D3-ключем. Довільні зовнішні індекси API не приймає. Pair-клітина посилається тільки на вже створені значення, тому цей обмежений механізм не створює циклів.

Перед кожною формою arena очищується; після успіху або семантичної помилки AST звільняється й arena скидається. Назовні повертаються власні байти `RawByteString`, які не посилаються на AST/arena. Це не persistent environment, не GC-інтеграція та не замикання.

Окремі межі: клітини (типово 4096, максимум 65536), кроки (16384, максимум 1048576) та глибина (128). Перевищення дає позиційний `ENativeEvalError`, після якого той самий evaluator придатний для наступної форми. Конструктор відхиляє недопустимі бюджети. Range/overflow/I/O checks та `heaptrc` увімкнені в тестовій збірці.

## Важлива межа текстової проєкції

Quote-текст у чинному SENS є структурою D7, а не Common Lisp symbol. Окремі UTF-8 літери зв'язуються через **pinned D7-таблицю**, без власного алфавіту Pascal або Unicode-арифметики, що вигадує біти. Порожні та вкладені списки зберігають структуру. Не підтримані тут лапковані рядки, числові літерали, escape reader syntax, префіксний апостроф і dotted source syntax відхиляються. Dotted **результат** від пари, створеної D3:111, підтриманий.

## Запуск і перевірки

Увімкнути наявний Guix-профіль Lazarus (або середовище `manifest.scm`) і з кореня репозиторію:

```sh
export PATH="$HOME/.guix-profiles/wsm-lazarus/bin:$PATH"
./scripts/sync-authority.sh
bash scripts/test-nativeeval.sh
./scripts/test.sh
build/m0.2/bin/test-nativeeval external/sens --eval '(сполучити так ні)'
```

Локальний FPC **3.2.2**: native-тести пройдено, `heaptrc` показав **0 невивільнених блоків**. До реалізації той самий тест падав на quote/D7, а не просто перевіряв наявність файлу. Повний існуючий headless gate теж пройшов; тести підключено через вільний `scripts/build.sh`, без змін чужих workflow/binder/GC-файлів.

Фізичні свідки потребують реально зібраного pinned SENS із Zig/T5M. У середовищі, де він запускається:

```sh
python3 scripts/nativeeval-witness.py \
  --sens-root /path/to/clean/sens-at-exact-pin \
  --out build/nativeeval-physical
```

`witness.json` містить pin, SHA вихідного Pascal unit і обох бінарників, stdout/stderr/exit кожного запуску. `lazarus_base_sha` фіксує базовий checkout під час перевірки; hash unit прив'язує доказ до зміненого коду до створення коміту. Позитивні й негативні `.sens` зберігаються поруч. За відсутності інструмента або розбіжності script завершується помилкою, без фальшивого PASS. Hosted CI підтверджує механічний FPC-тест, а локальний physical witness є окремим шаром доказів.

## Що лишається недоробленим

Повні D3 (EQ/COND), D4+ застосування, числа D12+, closures, лексичні user bindings, macro, runtime/GC-з'єднання, canonical binary reader у Pascal, Core4 execution, REPL, backend і системний образ **не реалізовані цим зрізом**. #41 та #44 залишаються відкритими. Нативний SIR1 також не перетворився на виконуваний компілятор.

## Чотири питання до цього коду

1. Чому в pair зберігається `SizeInt`-індекс, а не адреса клітини, і що з ним відбувається після `SetLength`?
2. Де саме в коді гарантується, що `D1:0` і `D3:000` не стануть одним host-false?
3. Чому `(як-є кіт)` повертає D7-список, а не Pascal-рядок чи interned symbol?
4. Які частини цього зрізу визначає закон SENS, а які — arena, budgets та layout Free Pascal?
