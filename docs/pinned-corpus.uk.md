# Доказ перенесення справжніх закріплених свідків SENS до FPC

**Завдання:** G2.14 у [#43](https://github.com/juv4uk/wsm-lazarus/issues/43), семантичний авторитет — **тільки** pinned `juv4uk/sens` за `external/sens` / `refs/tier1-baseline.properties`. Ця перевірка не змінює pinned файли, не копіює бібліотечну семантику і не називає структурний reader компілятором.

## Фактичні дані, не саморобні приклади

Після штатного `./scripts/sync-authority.sh` виконайте `bash scripts/test-pinned-corpus.sh`. Команда `git show PIN:path` бере **оригінальні об'єкти exact pinned commit**, навіть якщо вони поза обмеженим sparse checkout. Програма будує чинні `senst5m`, `sensbind`, `sensholovy` та `sensshyryna` справжнім FPC 3.2.2 із range/overflow/I/O перевірками.

- `examples/migrated/smoke-quote.lisp`, `.sens`, `smoke-quote` (видимі точні біти без розширення).
- `examples/migrated/smoke-cond.lisp`, `.sens`, `smoke-cond`.
- `tests/oracles/d1-cond-law/proof.sens` та `proof` — справжній корпус D1/COND з ратифікованого джерела, **не** незалежний оракул FPC.
- `tests/semantic/d5-d12-numberp-law.lisp`, `.sens`, `d5-d12-numberp-law` — справжній numeric-свідок. Його фізичні слова мають **24 біти**, попри назву з D12: лексема/назва файлу не заміняє exact width. `sensshyryna` підтверджує тільки D24-шири́ну/біти/адреси, а чинний вузький D2 binder чесно відхиляє W24.

Доказ для кожного фізичного прикладу — `senst5m --перегляд` **байт-у-байт** рівний бітовому файлу upstream і повторний `--пакувати-слова` відновлює **той самий** `.sens`. Людський український `.lisp` читається окремо через `sensbind --analyze` як структура, без твердження про однакове виконання. Пошкоджений T5M 243 і W24 у неготовому binder відхиляються без часткового stdout.

## Числа, українські проєкції та справжні межі

За чинним `contracts/language-contract-12.lisp` та `contracts/numeric-domains-ratification.lisp` **окрема числова драбина починається з D12**, далі D24/D48/D96/D192. Точний двійковий транспорт сам по собі не ратифікує математичне значення. Додаткова літерна `укр` у людському `.lisp` — проєкція; не переписувати її в host-команди й не приписувати `D5` математичного *значення* лише тому, що функція має математичне призначення. Для чисел закон окремий, потрібна відповідність реальному SENS REPL.

Це механічний переносимий доказ для іншого субстрату, **не** незалежне підтвердження arithmetic, Core4, українського source↔binary round-trip чи семантики COND. Коли з'явиться exact реальний oracle-результат SENS REPL, його можна зіставити окремим тестом; тут навмисно не створено саморобного семантичного oracle.

## П'ять принципів із кореневого SENS

[Чинний проектний документ](https://github.com/juv4uk/sens/blob/main/docs/language-core-axioms.md) сформулював п'ять принципів, не п'ять нових opcode:

1. **Писати про можливості**: переносимо реальні свідки на FPC/Lazarus.
2. **Бути Lisp у повному розумінні**: людський код — спискова українська проєкція, а бінарна структура зберігає тотожність.
3. **Розумна машина / Advice Taker**: відтворюваний фундамент потрібен для майбутнього символьного reasoning, не вдаємо готовий reasoning.
4. **Універсальність**: перевіряємо *ті самі* pinned фізичні свідки на іншому реалізаційному субстраті.
5. **Сучасні технології для символьного ШІ**: точний commit SHA, GitHub-hosted FPC, незалежні негативні та відтворювані тести.

Без фізичного датчика енергії — `ENERGY_NOT_MEASURED`, без тверджень про швидкодію. `#43` і `#41` залишаються відкритими до law-backed викличності та виконання.
