# Енергія інтерактивного SENS REPL

Стенд порівнює однакові послідовності українських форм у сталому сеансі нативного Core1 REPL і pinned незалежного SENS REPL. Він зберігає кожне читання RAPL і перевіряє точну кількість відповідей.

Форма-свідок: `(додати 5000 5000)`, результат `10000`. Вхідні десяткові операнди перевіряються як два точні D24-слова у фізичному T5M, створеному pinned читачем SENS. Перед вимірюванням обидва REPL виконують свідок та мусять повернути той самий результат.

## Запуск

Збірки виконуються поза RAPL-вимірюванням. Команда нижче читає апаратний лічильник через sudo, але запускає REPL-процеси від звичайного користувача:

```sh
sudo -E python3 scripts/energy/repl-core1-benchmark.py \
  --root "$PWD" \
  --sens /home/agents/GitHub/sens/target/release/sens \
  --core1 "$PWD/build/energy/core1-repl/bin/senscore1repl" \
  --output "$PWD/evidence/energy-repl-core1-20261029/repl-30x.json" \
  --forms 10000 --rounds 30 --core 2
```

Для відтворюваності збережіть SHA репозиторію SENS, версію REPL, FPC build, стан системи та повний JSON із сирими показниками. Датчик читається кожні 50 мс; порядок Core1, SENS та простою перемішується з фіксованим seed.

## Межі вимірювання

Linux на цій машині надає RAPL для всього пакета CPU, а не окремого процесу. Тому джоулі включають браузер, ядро та будь-яке інше навантаження. Простій і системні лічильники записуються як контекст, але з них не віднімається «енергія процесу». Результат є дослідним парним вимірюванням конкретного REPL-сеансу, а не рейтингом мов або доказом енергоефективності компілятора. Якщо фоновий шум перекриває різницю, чесний висновок — енергетичний переможець не визначений.

Core1 допускає 92 з 96 pinned визначень; REPL підтримує користувацькі визначення, але ще не реалізує повну мову чи GC. Збірки, завантаження authority та GUI не входять до workload; запуск REPL-процесу входить у часову, CPU та RAPL-ділянку.

## Вимір 2026-10-29

На Intel Core i5-6400, Linux 7.0.0-42, з прив'язкою до CPU 2 виконано 30 рандомізованих блоків, по 10 000 форм у кожному REPL-сеансі. SENS authority: `1f1bf676eeac605e065035d9dd2adaae807f1788`; SENS CLI 0.42.3; Core1 зібраний FPC 3.2.2.

| Вимір | Core1 REPL | SENS REPL |
|---|---:|---:|
| Медіанний час повного запуску 10 000 форм | 1,039 с | 3,019 с |
| Медіанний CPU time дочірнього процесу | 0,973 с | 2,944 с |
| Пропускна здатність | 9 627 форм/с | 3 312 форм/с |
| Медіанна енергія RAPL package за сеанс | 28,46 Дж | 80,77 Дж |
| Груба оцінка після віднімання idle-потужності пакета | 6,59 Дж | 19,90 Дж |

У цьому конкретному workload Core1 завершив сеанс приблизно у 2,91 раза швидше. Парна bootstrap-оцінка різниці idle-скоригованої пакетної енергії `Core1 − SENS` становить −13,76 Дж на 10 000 форм, 95% percentile-інтервал [−17,66; −10,96] Дж. Це не є виміром енергії процесу: RAPL включає пакет CPU та фонові процеси, а idle-корекція лише наближена. Сирі 90 вимірювальних інтервалів, усі межі лічильників, температура, завантаження, походження бінарників і статистика збережені в [повному JSON-звіті](../evidence/energy-repl-core1-20261029/repl-30x.json).

Фізичний свідок збережено як [українське джерело](../evidence/energy-repl-core1-20261029/witness/add-d24.lisp) та [паковані T5M-слова](../evidence/energy-repl-core1-20261029/witness/add-d24.sens). В обох операндах T5M міститься точне 24-бітне слово `000000000001001110001000`.
