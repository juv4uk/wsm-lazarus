# Перша дослідна енергетична серія SENS

Задача: [#346](https://github.com/juv4uk/wsm-lazarus/issues/346).

## Що реально виміряно

29.10.2026, 13:01:49–13:03:51 UTC: 30 блоків із перемішаними
трьома D3-навантаженнями та простоєм стенда, разом **120 замірів і
2493 набори читань RAPL**. Intel Core i5-6400, 4 фізичні ядра, Linux
7.0.0-42-generic, Free Pascal 3.2.2, `-B -O2 -Mobjfpc`, governor
`powersave`, Turbo дозволений. CPU affinity виконавців — ядро 2.
Root читає датчики, FPC-процеси працюють як `agents`.

Використано чинний `TBinaryExecutor.ExecutePhysicalT5M`, без нового evaluator.
Кожний повтор включає T5M decode, D2 parse, exact binder, виконання й
канонічне пакування відповіді. Файл прочитано та authority завантажено до
початку серії; створення процесів, компіляція, Oracle та GUI не входять до
наведених замірів. Це **не чистий native backend** і не вимір повного холодного
запуску. Повторення — host-механізм стенда, не цикл мовою SENS.

Знімок основного коду: `87670dcb0ecee51fdaf19c7d4fc2012770e86064` плюс нові
файли стенда; їхні хеші й dirty-state зафіксовані в сирому звіті. Авторитет:
`juv4uk/sens@1f1bf676eeac605e065035d9dd2adaae807f1788`, Contract 12.0.

## Межі висновку

**Стенд спільний із графічним сеансом та Firefox.** Медіанний сторонній CPU
час становив приблизно 1,22–1,32 активного ядра протягом замірів; під час
простою самого стенда — 1,23. Частоти й Turbo не фіксувалися, температури
та кожне сире читання збережено. Компіляції перед серією завершено.

RAPL показує енергію апаратних зон, включно зі сторонньою роботою та
колектором. Тому наведені джоулі **не приписуються лише процесу SENS**.
Поле `metadata.excluded` сирого звіту описує тільки виключення з
вимірюваного шляху програми; зокрема `GUI` не означає виключення енергії
графічного сеансу з апаратного лічильника.
Великий розкид idle baseline не дозволяє чесно просто відняти його від
медіан навантажень та назвати різницю чистою енергією програми.
Перевага над C/Rust/FPC, мінімальне енергоспоживання, числова арифметика
D12+ і загальна підтримка SENS цією серією не доведені.

## Правильність і свідки

Фізичні `.sens`, їхні `.words` та обернені `укр` `.lisp` проєкції лежать у
[`evidence/energy-baseline-20261029`](../evidence/energy-baseline-20261029).
Усі три програми перед вимірюванням виконано незалежним pinned Rust/Zig
SENS REPL: рівність → `ТАК`, селектор → `НІ`, умова → `ТАК`. Журнали та хеш
оракула — `*.repl.txt`, `oracle.json`. Rust 1.99.0, Zig 0.16.0; їхня робота
не входила до RAPL серії.

Кожний виміряний виклик додатково звіряє exact канонічні байти відповіді;
host checksum підтверджує кількість повторів, не замінюючи цієї перевірки.
`report.json.gz` містить повний UTF-8 JSON: метадані, усі читання, температури,
CPU час виконавців і фону, RSS та підсумки. Суми RAPL враховують оберт
лічильника; надмірний інтервал опитування відхиляється за описаною в коді
консервативною межею 1000 Вт для цього desktop стенда. Це не налаштування CPU.

## Відтворення

Із кореня репозиторію, після матеріалізації pinned `external/sens`:

```sh
python3 -m unittest discover -s scripts/energy -p test_measure.py
bash scripts/energy/build.sh
```

Перед новою серією окремо перевірити всі `build/energy/fixtures/*.lisp`
через справжній REPL на тому самому pinned SHA та зберегти transcript.
Після завершення всіх складань:

```sh
sudo python3 scripts/energy/measure.py \
  --root "$PWD" --output "$PWD/build/energy/new-report.json" \
  --rounds 30 --seconds 1 --core 2 --seed 346
```

Файл призначення має бути новим. Відсутність датчика/прав, неправильна
відповідь, timeout або пошкоджений лічильник не створюють успішний звіт.
CI перевіряє механіку і FPC-програми, але повідомляє `ENERGY_NOT_MEASURED`.
Сирий звіт цієї серії читається командою:

```sh
gzip -dc evidence/energy-baseline-20261029/report.json.gz | python3 -m json.tool
```

Наступний крок #346 — повторити на тихій контрольованій машині, додати
окремі режими холодного запуску/native backend і еквівалентні реалізації
C/Rust/FPC. Перший базовий звіт не закриває всю задачу.
