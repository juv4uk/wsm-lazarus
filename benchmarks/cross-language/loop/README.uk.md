# Навантаження `loop` — друге зі списку pinned SENS

Тіло в усіх близнюках **одне**:

```
acc = 0
N разів: acc = acc + K
код виходу = acc & 255
```

`N` — параметр навантаження (ресурс хоста), `K` — стала. Це **вузьке
навантаження** для порівняння швидкості й енергії, а не доказ повноти
компілятора SENS.

## Близнюки

| мова | файл | як збудувати |
|---|---|---|
| SENS (нативний) | механізм `src/wsm.elfd12loop.pas` + `src/sensd12loop.lpr` | `scripts/test-d12loop.sh` (35 перевірок) |
| C | `loop.c` | `gcc -O2 -DLOOP_N=<n> -DLOOP_K=<k>` |
| Rust | `loop.rs` | `rustc -O` (`LOOP_N`, `LOOP_K` — змінні середовища) |
| Free Pascal | `loop.pas` | `fpc -O2` (аргументи: `<n> <k>`) |

SENS-бік тут **не переписано**: нативний цикл дає чинний механізм
`wsm.elfd12loop`, який бере D12-сталу з pinned `.sens` і має власний
тест. Цей каталог додає три програмні близнюки й звірку з оракулом.

## Перевірка

```sh
./scripts/run-loop-twins.sh
```

Скрипт **нічого не міряє** без `--measure`: він доводить, що близнюки
рахують те саме. Оракул — арифметика `(N*K) mod 256`, а не цикл: він не
залежить від швидкості хоста й не може зійтися з близнюком через спільну
помилку лічби.

## Чесні межі

- GCC і Rustc у пісочниці розробки відсутні — їх збирає CI.
- `N` і акумулятор — **host-параметри** навантаження, не закони SENS.
- Це не доводить, що SENS-компілятор обробляє довільні цикли: нативний
  цикл будується з точної D12-сталої, а не з довільного тіла.
