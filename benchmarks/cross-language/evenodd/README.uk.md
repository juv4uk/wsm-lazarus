# Навантаження `evenodd` — четверте зі списку pinned SENS

Тіло в усіх близнюках **одне** — взаємна рекурсія двох функцій:

```
even(n) = 1, якщо n < 1;  інакше odd(n-1)
odd(n)  = 0, якщо n < 1;  інакше even(n-1)
код виходу = even(n) & 255
```

Тобто `1` для парних і `0` для непарних. Це навантаження перевіряє те,
чого не перевіряють `fib` і `ackermann`: **виклик уперед** до функції,
якої ще немає в буфері емісії.

## Близнюки

| мова | файл | як збудувати |
|---|---|---|
| SENS (нативний) | `LowerPairELF` у `src/wsm.lowerd24.pas` | `scripts/test-lowerd24.sh` (випадки `парне/непарне`) |
| C | `evenodd.c` | `gcc -O2` (аргумент: `<n>`) |
| Rust | `evenodd.rs` | `rustc -O` (аргумент: `<n>`) |
| Free Pascal | `evenodd.pas` | `fpc -O2` (аргумент: `<n>`) |

## Перевірка

```sh
./scripts/run-evenodd-twins.sh
```

Скрипт **нічого не міряє** без `--measure`. Оракул тут — не «те саме
тіло іншою мовою», а **незалежна властивість числа**: `n % 2 == 0`.
Це сильніше за переписування тіла, бо не поділяє з близнюками жодної
гілки логіки.

## Чесні межі

- GCC і Rustc у пісочниці розробки відсутні — їх збирає CI.
- `n` — параметр навантаження, не закон SENS.
- Глибока рекурсія обмежена стеком; великі `n` тут не є метою.
- Час у цьому навантаженні не публікується: на доступних `n` він
  тоне в запуску процесу.
