# D12 ділення: холодний запуск чотирьох виконуваних файлів

Цей стенд порівнює **одну вузьку операцію**: точне signed D12-ділення, коли дільник ненульовий, частка цілочисельна і результат залишається в D12. Він не вимірює повний компілятор, загальну мову чи процес окремо.

## Вхід і виконання

Усі workers читають ту саму фізичну рамку: два окремі 12-бітні signed значення, закодовані шістьма канонічними байтами T5M. Результат — одне D12 слово у трьох канонічних T5M байтах. Допуск фізичного SENS якоря D5:10111 і виконуваний SENS ELF беруться з чинного `sensd12quotpotikelf`; C, Rust і Free Pascal мають окремі малі транспортні workers. Їхня T5M реалізація тут — host-транспорт і не є таблицею законів SENS.

Перед будь-яким виміром збираються чотири ELF, звіряються 25 runtime пар із незалежним pinned `sens-oracle` REPL і перевіряються 18 негативних рамок/числових меж для кожного виконавця. Виміряні програми вже скомпільовані: тривалість збірки не входить у runtime результат. Кожен процес робить одну операцію, читає однакову рамку та віддає точні однакові байти.

## Запуск

Перевірити збірку, фізичний parity та pinned oracle, не створюючи енергетичного звіту:

```sh
./scripts/energy/run-quot-runtime-benchmark.sh --verify
```

Локальний RAPL вимір вимагає доступної Intel package зони; helper використовує `sudo -n` лише для читання RAPL, якщо звичайному користувачу бракує дозволу. Вихідні файли мають бути новими й в одній наявній теці:

```sh
./scripts/energy/run-quot-runtime-benchmark.sh --measure \
  --output benchmarks/cross-language/quot/evidence/run.json \
  --samples benchmarks/cross-language/quot/evidence/run.jsonl
```

За відсутності датчика або дозволу програма відмовляє з `ENERGY_NOT_MEASURED` і не пише джоулі. Для відтворюваного повтору додавайте нові назви файлів; наявний звіт ніколи не перезаписується.

## Інтерпретація

RAPL читає весь CPU package. Вимір включає запуск процесу, ОС, передавання кадру, T5M transport, ділення, вивід і два запуски helper-а для RAPL-знімків; idle контроль зберігається, але не віднімається. Медіана package-дельти, поділена на кількість повторних холодних викликів у вибірці, є нормалізацією цього конкретного end-to-end інтервалу, а не енергією PID чи чистою вартістю `IDIV`. Це не підтримує рейтинг усіх програм або мов.

Workflow `.github/workflows/benchmark-d12-quot-energy.yml` має лише `workflow_dispatch`. Він запускає функціональну parity-перевірку, але не RAPL; hosted runner не подає фізичні джоулі. Rust/Zig pinned REPL build відбувається тільки за ручним запитом, не на push або PR.

## Виміряний зріз 2026-10-30

На цьому host виконано 30 рандомізованих блоків, чотири однакові runtime-пари на кожну мову, 12 окремих холодних процесів у кожній RAPL вибірці та 30 idle-контролів. Насіння порядку — `6176`. Джерело — Intel package `intel-rapl:0`, CPU Intel Core i5-6400, Linux `7.0.0-42-generic`, governor `powersave`, Turbo увімкнений. Збірки: GCC `13.3.0 -O2`, Rust `1.99.0 -C opt-level=2`, FPC `3.2.2 -O2`; SENS — 1 306-байтовий ELF64 із фізичного pinned D5-якоря та runtime T5M кадрами.

| Виконавець | Медіана package ΔE / 12 холодних запусків | Медіанний час / запуск |
|---|---:|---:|
| SENS ELF | 0,03676 Дж | 2,859 мс |
| C/GCC | 0,05128 Дж | 3,393 мс |
| Rust | 0,05643 Дж | 3,669 мс |
| Free Pascal | 0,04573 Дж | 3,166 мс |

Парні медіанні різниці `контроль − SENS` після нормалізації на 12 запусків за 120 пар `(блок, D12-пара)` були: C/GCC `+0,01315 Дж` (95% percentile-bootstrap CI `+0,00971…+0,01647`), Rust `+0,01842 Дж` (`+0,01612…+0,02003`), Free Pascal `+0,00771 Дж` (`+0,00585…+0,01002`). Для кожної різниці повторено 20 000 bootstrap-вибірок; seeds `6177`, `6178`, `6179`. Позитивна парна різниця була відповідно у 82,5%, 90,8% і 76,7% пар.

Повний звіт із SHA чотирьох ELF — [`evidence/rapl-20261030.json`](evidence/rapl-20261030.json); усі 510 сирих інтервалів RAPL — [`evidence/rapl-20261030.jsonl`](evidence/rapl-20261030.jsonl). У тому самому запуску 100/100 позитивних виконань мали однакові фізичні результати, 25/25 пройшли pinned SENS REPL, а 72/72 негативні запуски відмовили без stdout.

Цей один вимір показує, що саме цей спеціалізований SENS ELF мав нижчу медіану нормалізованої package-дельти в цій конфігурації. Він **не доводить**, що SENS загалом енергоефективніша: RAPL охоплює весь CPU package, а холодний запуск, I/O та RAPL helper-и становлять значну частину вимірюваного інтервалу. Це також не оцінка часу чи енергії компіляції.
