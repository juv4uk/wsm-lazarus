# Навантаження `ackermann` — третє зі списку pinned SENS

Тіло в усіх близнюках **одне**:

```
ack(m,n) = n + 1                    якщо m = 0
         = ack(m-1, 1)              якщо n = 0
         = ack(m-1, ack(m, n-1))    інакше
код виходу = ack(m,n) & 255
```

`m` і `n` — параметри навантаження. Це **вузьке** навантаження: глибока
рекурсія з двома параметрами й вкладеним викликом в аргументі.

## Близнюки

| мова | файл | як збудувати |
|---|---|---|
| SENS (нативний) | зниження `src/wsm.lowerd24.pas` | `scripts/test-lowerd24.sh` (випадки `акерман`) |
| C | `ackermann.c` | `gcc -O2` (аргументи: `<m> <n>`) |
| Rust | `ackermann.rs` | `rustc -O` (аргументи: `<m> <n>`) |
| Free Pascal | `ackermann.pas` | `fpc -O2` (аргументи: `<m> <n>`) |

SENS-бік **не переписано вручну**: тіло збирається з точних слів і
знижується `wsm.lowerd24` у x86-64; ті самі пари `(m,n)` перевіряє
`LOWER24-PASS`.

## Перевірка

```sh
./scripts/run-ackermann-twins.sh
```

Скрипт **нічого не міряє** без `--measure`. Оракул написано **іншою
мовою** (Python), а не тим самим кодом: інакше спільна помилка в
реалізації «зійшлася» б сама з собою і виглядала б як успіх.

**Чому не awk.** Перша версія оракула була на awk — і падала з
`program limit exceeded: eval stack size=1024` вже на `ack(3,8)`.
Це не дрібниця: без оракула «звірено» перетворюється на неправду.
Python із `setrecursionlimit` тримає `ack(3,7)` і глибше.

## Час тут не міряється — і ось чому

На безпечних для оракула розмірах (`ack(2,3)`, `ack(3,5)`, `ack(3,7)`)
мінімум із 5 прогонів — **18–28 мс**, і це майже повністю запуск
процесу, а не робота. Публікувати такі числа як «швидкість ackermann»
було б обманом. Чесний вимір потребує або повторів усередині процесу,
або розмірів, де результат уже не влазить у 8-бітний код виходу.

Тому в цьому навантаженні публікується **збіг результатів**, а не час.

## Чесні межі

- GCC і Rustc у пісочниці розробки відсутні — їх збирає CI.
- `m` і `n` — параметри навантаження, не закони SENS.
- Глибока рекурсія обмежена стеком; `ack(4,1)` і далі не є метою цього
  навантаження.
