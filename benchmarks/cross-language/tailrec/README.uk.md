# Хвостова рекурсія — навантаження, де важлива не швидкість, а межа

Тіло в усіх близнюках **одне**:

```
count_down(n, acc) = acc,            якщо n < 1
                   = count_down(n-1, acc+1)   інакше   (самовиклик — хвіст)
код виходу = count_down(n, 0) & 255 = n & 255
```

Це навантаження перевіряє **межу глибини**, а не швидкість. Без хвостової
оптимізації `n = 1 000 000` — це мільйон кадрів і гарантоване переповнення
стека. З нею — стала пам'ять.

## Близнюки

| мова | файл |
|---|---|
| Free Pascal | `tailrec.pas` |
| C | `tailrec.c` |
| Rust | `tailrec.rs` (важкий тулчейн: лише вручну) |

Оракул — не переписане тіло, а **властивість**: `count_down(n, 0) = n`,
тому очікуваний код виходу `n & 255`.

## Перевірка

```sh
./scripts/run-tailrec-twins.sh          # лише звірка
./scripts/run-tailrec-twins.sh --measure  # плюс таймінги з походженням
```

## Чесні межі

- Час тут не показник: на доступних `n` він тоне в запуску процесу.
- SENS-бік: зниження вже має **однопараметрову** хвостову рекурсію
  (`LOWER24-PASS`, n=5 000 000). Двопараметровий хвостовий виклик
  знімає кадр правильно (виправлено в G6.156), але тіло з накопичувачем
  ще не доведене до зеленого тесту — тому SENS-стовпця в таблиці немає.
  Це чесний борг, а не «працює».
- Rust не збирається на кожен пуш — політика ваги (#805).
