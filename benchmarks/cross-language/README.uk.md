# Міжмовні навантаження: політика ваги

Ми міряємо **енергоефективність**. Тому інфраструктура вимірювання сама
не має права бути енергогарною — інакше бенчмарк споживає більше, ніж
вимірює.

## Правило

**На кожен пуш важкі тулчейни НЕ збираються.**

| інструмент | коли запускається |
|---|---|
| FPC | завжди (швидкий, і це наш основний компілятор) |
| GCC | завжди (швидкий) |
| Rust | **лише явний запуск** із `rust: true` у `workflow_dispatch` |
| RAPL-вимір | лише на машині з лічильниками, ніколи в CI |

Тригери `push` у прогнах близнюків прибрано: вони бігають на
`pull_request` (за шляхами) і на явний `workflow_dispatch`.

## Навіщо саме так

- `rustc` — важкий тулчейн: довга збірка й помітне споживання. Для
  перевірки **збігу результатів** достатньо FPC і GCC; Rust потрібен для
  повноти картини, а не для кожного коміту.
- Числа швидкості й енергії публікуються лише з походженням (SHA, CPU,
  версії компіляторів) і ніколи — з CI-раннера, бо він шумний.

## Навантаження

| навантаження | SENS-бік | близнюки | оракул |
|---|---|---|---|
| `fib` | зниження D24 | C, Rust, FPC | ітеративний fib |
| `loop` | D12-цикл | C, Rust, FPC | формула `(N*K) mod 256` |
| `ackermann` | зниження (два параметри) | C, Rust, FPC | Python, та сама математика |
| `evenodd` | `LowerPairELF` (взаємна рекурсія) | C, Rust, FPC | `n % 2 == 0` — незалежна властивість |
