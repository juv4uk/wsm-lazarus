# G6.138 — міжмовне порівняння енергії Fibonacci на справжньому CPU

Цей протокол **не публікує вигаданих джоулів**. Порівняння використовує
наявні фізичні SENS D24 тіла і три вже наявні програмні близнюки:

- SENS: `src/sensfiblower.lpr` породжує справжній Linux x86-64 ELF із
  бінарного тіла SENS через pinned `external/sens` / `wsm.lowerd24`.
- C: `fib.c`, компіляція `gcc -O2 -DN=<n>`.
- Rust: `fib.rs`, компіляція `rustc --edition 2021 -O`.
- Free Pascal: `fib.pas`, компіляція `fpc -O2`.

В усіх чотирьох одна математична рекурсія
`fib(n)=n (n<2), інакше fib(n-1)+fib(n-2)`.
Кожна програма повертає `fib(n) & 255` як **host exit status**.
Перед вимірюванням ВСІ чотири результати перевіряються через незалежний
ітеративний арифметичний оракул. Це порівняння **вузького навантаження**,
а не загального компілятора SENS, його Core1/Core4 чи REPL.

## Запуск

На Linux x86-64 із FPC, GCC, Rustc та Python 3:

```sh
FIB_N=35 ./scripts/run-fib-energy-cross.sh --verify
FIB_N=35 FIB_REPEATS=5 ./scripts/run-fib-energy-cross.sh --measure
```

Перший режим **тільки збирає й перевіряє 4 справжні виконувані файли**.
Другий додатково вимагає ЧИТАБЕЛЬНИЙ **апаратний Linux RAPL**:
`/sys/class/powercap/intel-rapl:0/name=package-0`,
`energy_uj` і `max_energy_range_uj`. За відсутності доступу до
лічильників — код 2, жодної енергетичної таблиці. Не використовувати
`sudo chmod` автоматично; доступ налаштовується окремо власником машини.

## Метод та межі

Фіксуємо SHA, версії компіляторів, модель CPU, N та число повторів.
Кожен програмний близнюк запускається окремо; порядок обертається по
раундах (SENS, C, Rust, FPC), прогрів не входить у таблицю. Використовуємо
монотонний таймер для мікросекунд і `energy_uj` для **мікроджоулів**.
Обробка можливого одного переповнення використовує **саме**
`max_energy_range_uj`, а не константу 1e9; надто довгі прогони,
для яких неможливо гарантувати менше двох циклів лічильника за
консервативної межі 500 Вт, відхиляються. Результат — медіана та
діапазон за 5 запусками, не безпідставна оцінка точності.

**Важливо:** `package-0` вимірює споживання ЦІЛОГО пакета процесора,
а не ізольовану енергію процесу; враховує фонові задачі, інші ядра та
накладні витрати запуску. Не включає обов'язково DRAM чи окрему GPU,
не є ватметром «від розетки». Не можна порівнювати результати різних
машин або робити висновок про узагальнену перевагу мови. За малих N
домінує startup; для ґрунтовного висновку потрібні серії на одному
виділеному комп'ютері з додатковими розмірами задач.

`--mock-root` у Python-вимірювачі призначено **виключно для механічних
тестів**, які завжди пишуть
`СИМУЛЬОВАНО-НЕ-ФІЗИЧНА-ЕНЕРГІЯ`. Запуск shell `--measure`
не приймає mock і ніколи не представляє тестові значення як апаратні.
CI перевіряє збирання, 4 коди виходу, арифметику переповнення та
відмови — **без заяви про вимірювання фізичних джоулів на runner**.

**Джерело формату лічильника:** документація Linux kernel
`Documentation/power/powercap/powercap.rst`,
`energy_uj` та `max_energy_range_uj`.
